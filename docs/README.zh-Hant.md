# Codex 額度守衛 0.4.1

[简体中文](../README.md) · [繁體中文](README.zh-Hant.md) · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

額度守衛會讀取帳號的實際額度，在 5 小時額度不足時自動暫停對話、將新請求排入佇列，並在額度恢復後回到原對話繼續執行。等待期間可讓電腦保持喚醒。修復版已取消透過使用者或系統層級的 `CODEX_CLI_PATH` 指定啟動程式的做法。即使監控故障，仍可照常啟動及登入 Codex。

## 舊版啟動故障的原因

桌面程式啟動時會執行 `app-server --print-startup-config --startup-client-info ...`，並將標準輸入設為 `ignore`。0.1 版的原生程式將這個單次查詢誤判為長時間運作的 RPC 工作階段。標準輸入結束後，Node 橋接程式關閉了連線，隨後又嘗試透過已關閉的 `Peer` 轉送啟動設定，導致設定輸出遺失。此外，它會在子處理程序觸發 `exit` 時結束輸出，未等到輸出串流讀完後的 `close` 事件。

使用本機原版 CLI 與 0.1 版原始碼進行比對時，原版 CLI 以結束代碼 0 傳回 **122 位元組的有效 JSON**。舊版橋接程式的結束代碼同樣為 0，輸出卻是 **0 位元組**。修復版傳回與原版相同的 **122 位元組有效 JSON**。這項測試重現並驗證了載入組織設定時的啟動相容性修正。實際桌面介面的組織設定與登入流程仍待迴歸測試。

## 兩種使用方式

**日常獨立監控**會另外啟動原版 CLI 的唯讀 `app-server`，完成初始化後，僅呼叫 `account/rateLimits/read`。系統匣與選用的 MCP 工具透過需要權杖的本機具名管道讀取狀態。查詢失敗、逾時、程式異常終止，或額度資料缺漏、過期時，介面顯示「暂不可用」（暫時無法取得），不會估算剩餘額度。

**完整自動守衛**可暫停並恢復工作。此版本的 Windows 桌面引擎使用專屬的標準輸入／輸出（stdio）通訊，沒有提供獨立監控程式可以連入的共用控制介面。因此，專用啟動指令碼會先驗證啟動設定與通訊協定，再為**這次桌面工作階段**啟用橋接程式。環境設定只套用到新啟動的桌面子處理程序。使用原有捷徑仍可照常開啟 Codex；指令碼不會改動使用者或系統環境變數，也不會強制關閉已開啟的桌面或向其中注入程式。

- 預設保留 5% 額度。服務回報的 5 小時（300 分鐘）額度剩餘量等於或低於門檻時，守衛會針對已連線引擎中所有已載入的對話，先儲存恢復記錄，再中斷執行中的工作，包括引擎看得到的子工作。
- 守衛會儲存新請求的原始參數，依用戶端識別碼排除重複請求，收到排入佇列的確認後才提交。若回應遺失或逾時，未獲確認的請求不會自動重送。
- 當 5 小時額度高於門檻，且帳號仍有使用權限時，下一次查詢或額度通知會觸發原對話繼續執行。預設每 30 秒查詢一次，每隔 1 秒嘗試重新連線。守衛會先確認實際額度，不會只根據預計重設時間啟動工作。
- 同一對話的請求依序執行，不同對話可平行執行。已取消、已封存或已另外繼續進行的舊回合不會被強制恢復。需要核准或輸入的事項仍由使用者決定。若無法確認請求是否已送達，守衛會標示為待人工核對，以免重複執行。
- 無法取得額度或監控失敗時，守衛會讓一般請求直接交給原版引擎，並暫停自動中斷與恢復操作。背景服務恢復後，橋接程式會重新連線。有工作排隊時，守衛可要求 Windows 暫緩睡眠；背景服務結束時會釋放這項要求。
- 守衛只控制從專用入口啟動且已連線的引擎。從一般入口啟動的 Codex、其他終端機及其他裝置不在控制範圍內。電腦睡眠、網路中斷或程式關閉期間，無法保證立即恢復工作。

## 安裝與重新啟用

需要 Windows、Node.js 22 以上版本，以及系統的 .NET Framework 4.x。請在**修復版的原始碼目錄**執行以下命令，避免使用舊快取中的指令碼。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-monitor.ps1
```

安裝程式會先執行檢查、測試與編譯，再更新外掛程式檔案。如果找不到可用的 CLI，獨立監控會顯示「暂不可用」。若舊版橋接程式仍在執行，安裝程式會停止覆寫。請先正常結束該工作階段或從系統匣結束舊版程式。安裝程式不會依處理程序名稱強制結束 Codex。更新獨立監控時，安裝程式會先停止外掛程式自己的背景服務與系統匣程式。更新完成後請再次執行 `start-monitor.ps1`。

需要自動暫停及恢復時，請先儲存工作並**正常完全結束 Codex**，再從 Codex 以外的 PowerShell 視窗執行以下命令。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-guarded-codex.ps1
```

啟動指令碼會從 Windows 應用程式資訊清單找出實際的桌面執行檔。它會先進行唯讀預檢，確認原版 CLI 與橋接程式回傳的一次性啟動設定相同，且初始化、`configRequirements/read` 與 `config/read` 均成功。預檢失敗時，會改用原版入口開啟桌面，保留獨立監控。這個流程不寫入使用者層級的環境變數，預檢也未涵蓋實際桌面介面的登入操作。桌面啟動後，帶有本次工作階段識別碼的引擎須完成交握；逾時會提示尚未確認連線。請在系統匣的「查看自动控制」確認已連線的引擎數量。顯示 0 表示目前只有獨立監控。

若要在 Codex 中重新註冊 MCP 工具，請執行 `install.ps1 -RegisterPlugin`，再前往 Codex 的外掛程式設定啟用本外掛。這個選項只會處理本外掛自己的市集與註冊資料，不會將監控標為 `required`。獨立監控與工作階段橋接都可以在 MCP 未連線時運作。`-AutoStart` 只會在 Windows 的「啟動」資料夾建立監控程式的系統匣捷徑，不會自動啟動或接管 Codex。

## 電子郵件提醒

守衛會透過已連結的 Gmail，將 5 小時與每週額度提醒寄到同一個收件地址。首次連結時，預設寄給自己。確認對話已中斷或暫緩執行後，守衛才會寄出 5 小時額度提醒。同一帳號在同一次低額度期間暫停多筆工作時，會合併通知。當獨立監控發現每週（10,080 分鐘）剩餘額度達到提醒門檻時，即使桌面引擎尚未連線，仍會寄出每週額度提醒，對話可繼續用完剩餘的每週額度。若服務只回報每週額度，5 小時額度狀態會顯示「暂不可用」。

安裝後執行以下命令，確認並連結目前的 Gmail 帳號。連結時只會讀取信箱身分並檢查工具是否可用。觸發提醒時，外掛會透過原版 CLI 的暫時工作階段直接呼叫 Gmail 寄信，信件內容僅含額度與時間資訊。若在寄出前失敗，守衛會延長等待時間後重試；若無法確認是否已寄出，系統匣的「查看额度」會顯示待核對。

```powershell
node "$env:LOCALAPPDATA/CodexQuotaGuard/app/scripts/connect-gmail.mjs"
```

如要把兩種提醒都寄到其他信箱，可用 `--recipient` 指定唯一的收件地址。請將下方範例地址替換為自己的收件信箱。

```powershell
node "$env:LOCALAPPDATA/CodexQuotaGuard/app/scripts/connect-gmail.mjs" --recipient "recipient@example.com"
```

同一個 Gmail 帳號再次連結時，省略參數會保留原本的收件地址。切換到其他 Gmail 帳號後，若未指定參數，預設會寄到新帳號本身的信箱。

## 一鍵還原與恢復使用

按兩下原始碼或安裝目錄中的 **`rollback.cmd`**，即可關閉自動控制，同時保留外掛、獨立監控與等待恢復的工作佇列。若專用入口曾記錄桌面處理程序，指令碼會核對 PID、完整執行檔路徑及啟動時間，確認身分後才結束該處理程序，再以一般環境開啟桌面。重新啟動會結束該工作階段中仍在執行的工作；若要保留執行中的處理程序，請使用下方不重啟桌面的命令。若 PID 已由其他處理程序使用，或身分與記錄不符，指令碼會拒絕終止處理程序。

如要只關閉自動控制並保留目前的桌面，請執行以下命令。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\rollback.ps1
```

即使背景服務異常終止，還原指令碼仍可離線關閉自動控制，並保留原有佇列。若工作記錄檔損毀，程式會保留原檔並回報問題，不會覆寫資料。若橋接程式本身異常終止，一般 Codex 入口仍可使用，也可透過一鍵還原重新開啟已記錄的桌面。**stdio 連線一旦中斷，就無法更換處理程序並完整接回原工作階段**，因此部分橋接故障需要重新開啟桌面。之後再次執行獨立監控及專用啟動指令碼，即可重新使用守衛，無須重新安裝或永久停用外掛。

## 舊版移轉、安全性與工具

只有 `scripts/migration.ps1` 在修復舊值時，才可能寫入持續生效的啟動環境變數。現有值必須完全符合已確認屬於本外掛的舊橋接程式路徑，才會從可信的備份還原或清除該值；寫入前會再次比對。原本未設定的值會維持未設定，其他路徑不會被覆寫，系統層級的值也不會套用使用者層級的備份。安裝過程不使用 `setx`，不直接修改登錄檔以覆寫啟動程式，也不安裝排程工作。

守衛不會刪除或改寫 Codex 的登入認證、工作階段、專案及其他外掛的設定。舊 `state.json` 會原樣保留，舊工作不會自動執行。新佇列儲存在 `automation-state.json`，其中包含等待恢復的請求內容。這個檔案與本外掛的權杖都存放於限制存取的外掛資料目錄。

本外掛提供八項 MCP 工具，包括 `guard_status`、`guard_check_now`、`guard_enable`、`guard_disable`、`guard_configure`、`guard_automation_status`、`guard_safe_mode` 與 `guard_cancel_pending`。啟用操作僅對現有連線生效，無法將已從一般入口開啟的桌面切換為守衛工作階段。離線時仍可初始化 MCP 並列出可用工具，這些操作不會啟動背景查詢服務。

下列命令可執行檢查、編譯、測試及診斷。執行 `doctor.mjs` 前，請將 `C:\path\to\codex.exe` 替換為本機**原版** `codex.exe` 的實際完整路徑。

```powershell
npm run check
npm run build
npm test
node .\scripts\doctor.mjs --backend "C:\path\to\codex.exe"
```

需要解除安裝時，請另外執行下列命令。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\uninstall.ps1
```

解除安裝時會停止本外掛的監控、移除自己的自動啟動項目、修復舊版的啟動覆寫設定，並保留資料。只有明確指定 `-RemovePlugin` 才會取消本外掛的註冊。在守衛工作階段中解除安裝後，請求仍會直接轉交原版引擎；請先正常結束工作階段，再刪除使用中的執行檔案。已驗證與尚待驗證的範圍詳見[修復驗證記錄](repair-validation.md)。
