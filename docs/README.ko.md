# Codex Quota Guard 0.4.1

[简体中文](../README.md) · [繁體中文](README.zh-Hant.md) · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

Codex Quota Guard는 서비스가 보고하는 실제 잔여 한도를 확인합니다. 5시간 한도가 부족해지면 작업을 일시 중지하고 새 요청을 대기열에 보관했다가 한도가 회복되면 원래 대화에서 재개합니다. 대기 중에는 Windows의 절전 모드를 막을 수도 있습니다. 사용자 또는 시스템 수준의 `CODEX_CLI_PATH`로 실행 경로를 바꾸던 방식을 제거했으므로, 모니터에 장애가 생겨도 일반 Codex 실행과 로그인에는 영향을 주지 않습니다.

## 이전 버전의 데스크톱 시작 오류

Codex 데스크톱은 시작할 때 표준 입력을 `ignore`로 두고 `app-server --print-startup-config --startup-client-info ...`를 실행합니다. 0.1의 네이티브 실행 파일은 이 일회성 설정 조회를 장시간 유지되는 RPC 세션으로 처리했습니다. 표준 입력이 끝나자 Node 브리지가 세션을 닫았고, 이후 이미 닫힌 Peer로 설정 응답을 전달하면서 출력이 유실됐습니다. 자식 프로세스의 출력 스트림이 비워진 뒤 발생하는 `close`보다 앞선 `exit` 시점에 출력을 끝내는 문제도 있었습니다.

같은 컴퓨터에서 원본 CLI와 0.1 소스를 비교한 결과, 원본 CLI는 종료 코드 0과 **유효한 JSON 122바이트**를 반환했습니다. 기존 브리지는 종료 코드가 0인데도 **0바이트**를 반환했고, 수정한 브리지는 원본과 동일한 **유효한 JSON 122바이트**를 반환했습니다. 조직 설정을 읽는 시작 경로의 호환성 문제는 이렇게 재현하고 수정했습니다. 실제 GUI의 조직 설정 화면과 로그인에 대한 회귀 테스트는 아직 수행하지 않았습니다.

## 두 가지 사용 방식

**독립 모니터**는 원본 CLI의 읽기 전용 `app-server`를 별도 프로세스로 실행해 초기화와 `account/rateLimits/read`만 수행합니다. 트레이와 선택 사항인 MCP 도구는 토큰으로 인증하는 로컬 파이프를 통해 상태를 읽습니다. 연결 실패, 시간 초과, 프로세스 비정상 종료, 데이터 누락 또는 만료 시에는 잔여량을 추정하지 않고 ‘일시적으로 확인할 수 없음’(실제 표시: ‘暂不可用’)으로 표시합니다.

**자동 일시 중지와 재개**에는 전용 실행 스크립트와 **해당 세션에만 적용되는 브리지**를 사용합니다. 현재 설치된 Windows 데스크톱 엔진은 전용 표준 입출력(stdio)으로 통신하며, 독립 모니터가 기존 엔진에 접속할 수 있는 공식 공유 제어 인터페이스를 제공하지 않습니다. 스크립트는 시작 설정과 프로토콜을 검증한 다음 새로 실행하는 데스크톱 자식 프로세스의 환경만 설정합니다. 일반 바로 가기와 사용자·시스템 환경 변수는 그대로 유지되며, 이미 실행 중인 데스크톱을 강제로 종료하거나 브리지를 삽입하지 않습니다.

- 기본 예비 한도는 5%입니다. 서비스가 보고한 5시간(300분) 구간의 잔여 비율이 이 값 이하가 되면 연결된 엔진에 로드된 모든 대화에서 재개에 필요한 기록을 저장하고 실행 중인 작업을 중단합니다. 엔진에서 확인할 수 있는 하위 작업도 대상입니다.
- 새 요청은 원래 인수와 함께 저장하며 클라이언트 식별자로 중복을 제거합니다. 대기열 등록 응답을 받은 요청만 확정합니다. 응답 유실이나 시간 초과로 등록을 확인할 수 없는 요청은 자동으로 다시 실행하지 않습니다.
- 5시간 구간의 잔여량이 임계값을 초과하고 계정에 사용 권한이 있으면 다음 조회나 한도 변경 알림을 계기로 원래 대화에서 작업을 재개합니다. 기본 조회 간격은 30초, 재연결 간격은 1초입니다. 예상 초기화 시간만으로 작업을 시작하지 않습니다.
- 같은 대화의 요청은 순서대로 처리하고 서로 다른 대화는 병렬로 처리할 수 있습니다. 취소되거나 보관된 대화, 사용자가 이미 별도로 진행한 이전 턴은 강제로 되살리지 않습니다. 승인이 필요하거나 사용자 입력을 기다리는 작업은 사용자의 결정을 기다립니다. 요청 전달 결과가 불분명하면 자동 재시도 대신 직접 확인하도록 표시합니다.
- 한도를 확인할 수 없거나 모니터가 실패하면 자동 중지와 재개를 수행하지 않고 일반 요청을 원본 엔진으로 직접 전달합니다. 백그라운드 서비스가 복구되면 브리지가 다시 연결됩니다. 작업 대기 중에는 절전 방지를 요청할 수 있으며 서비스가 종료되면 요청도 해제됩니다.
- 자동 제어는 전용 스크립트로 실행하고 브리지가 연결된 엔진에만 적용됩니다. 일반 방식으로 실행한 Codex, 다른 터미널이나 기기의 작업은 대상에 포함되지 않습니다. 컴퓨터가 절전 상태이거나 네트워크가 끊겼거나 프로그램이 종료된 동안에는 한도 회복 즉시 작업을 재개할 수 없습니다.

## 설치 및 다시 활성화

Windows, Node.js 22 이상, 시스템에 설치된 .NET Framework 4.x가 필요합니다. 아래 명령은 **수정본의 소스 디렉터리**에서 실행하세요. 이전 버전의 캐시에 남은 스크립트는 사용하지 마세요.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-monitor.ps1
```

설치 프로그램은 검사, 테스트, 빌드를 마친 뒤 플러그인 파일을 업데이트합니다. 사용할 수 있는 CLI가 없으면 독립 모니터에 ‘暂不可用’이 표시됩니다. 이 플러그인의 브리지가 실행 중이면 덮어쓸 수 없으므로 해당 이전 세션이나 이전 트레이 프로그램을 먼저 정상 종료하세요. 설치 스크립트는 프로세스 이름으로 Codex를 종료하지 않습니다. 독립 모니터를 업데이트할 때는 플러그인의 백그라운드 서비스와 트레이가 중지되므로 업데이트가 끝나면 `start-monitor.ps1`을 다시 실행하세요.

자동 일시 중지와 재개를 사용하려면 작업을 저장하고 **Codex를 정상적으로 완전히 종료**한 뒤, Codex 바깥의 PowerShell에서 다음 명령을 실행하세요.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-guarded-codex.ps1
```

스크립트는 Windows 앱 매니페스트에서 실제 데스크톱 실행 파일을 찾습니다. 시작 전 읽기 전용 검사에서 원본 CLI와 브리지의 일회성 시작 설정이 일치하는지, 초기화와 `configRequirements/read`, `config/read`가 성공하는지 확인합니다. 검사에 실패하면 사용자 환경 변수를 쓰지 않고 원래 실행 경로로 데스크톱을 열며 독립 모니터를 유지합니다. 데스크톱을 연 뒤에는 이번 세션의 식별자와 일치하는 엔진이 핸드셰이크를 마쳐야 합니다. 시간 내에 응답이 없으면 연결을 확인하지 못했다고 알립니다. 사전 검사는 실제 GUI 로그인 테스트를 대신하지 않습니다. 트레이의 ‘자동 제어 보기’(‘查看自动控制’)에서 연결된 엔진 수를 확인하세요. 0개이면 현재는 독립 모니터만 작동합니다.

Codex 안에서 MCP 도구를 다시 등록하려면 `install.ps1 -RegisterPlugin`을 명시적으로 실행한 뒤 Codex 플러그인 설정에서 이 플러그인을 활성화하세요. 스크립트는 자체 마켓플레이스와 플러그인만 등록하며 모니터를 필수(`required`)로 설정하지 않습니다. 독립 모니터와 세션 브리지는 MCP가 연결되지 않아도 작동합니다. `-AutoStart` 옵션은 Windows 시작프로그램 폴더에 모니터 트레이 바로 가기만 만듭니다. Codex 자체를 자동으로 실행하거나 제어하지 않습니다.

## 이메일 알림

연결한 Gmail 계정으로 5시간 한도와 주간 한도 알림을 보냅니다. 두 종류의 알림은 동일한 수신 주소 하나로 발송하며, 처음 연결할 때의 기본 수신자는 본인입니다. 5시간 알림은 대화를 중단했거나 새 요청의 처리를 보류한 사실이 확인된 뒤 보냅니다. 한 계정에서 같은 한도 부족 기간에 발생한 여러 작업은 하나의 알림으로 묶습니다. 독립 모니터에서 주간 구간(10,080분)의 잔여량이 임계값 이하로 확인되면 데스크톱이 연결되지 않아도 주간 알림을 보냅니다. 대화는 남은 주간 한도를 계속 사용할 수 있습니다. 서비스가 주간 구간만 제공하면 5시간 한도는 확인할 수 없다고 표시합니다.

설치 후 다음 명령으로 현재 Gmail 계정을 확인하고 연결하세요. 연결할 때는 메일 계정의 신원과 도구의 사용 가능 여부만 읽습니다. 알림이 발생하면 플러그인은 원본 CLI의 임시 세션에서 Gmail 발송 도구를 직접 호출합니다. 메일 본문에는 한도와 시간 정보만 포함됩니다. 발송 전에 실패하면 간격을 늘려 재시도합니다. 발송 결과가 불분명한 경우에는 트레이의 ‘한도 보기’(‘查看额度’)에 직접 확인이 필요하다고 표시합니다.

```powershell
node "$env:LOCALAPPDATA/CodexQuotaGuard/app/scripts/connect-gmail.mjs"
```

두 종류의 알림을 다른 메일함으로 받으려면 `--recipient`로 수신 주소 하나를 지정하세요. 예시 주소를 실제 수신 주소로 바꾸어 실행하세요.

```powershell
node "$env:LOCALAPPDATA/CodexQuotaGuard/app/scripts/connect-gmail.mjs" --recipient "recipient@example.com"
```

같은 Gmail 계정에서 인수 없이 다시 연결하면 기존 수신 주소를 유지합니다. Gmail 계정을 바꾼 뒤 인수 없이 연결하면 새 계정 본인의 주소가 수신자가 됩니다.

## 원클릭 롤백과 복구

소스 또는 설치 디렉터리에 있는 **`rollback.cmd`** 를 두 번 클릭하면 자동 제어를 끄고 플러그인, 모니터, 재개 대기열을 보존합니다. 전용 스크립트가 실행한 데스크톱의 기록이 있으면 PID, 실행 파일의 전체 경로, 시작 시각을 대조한 뒤 해당 프로세스를 종료하고 일반 환경으로 다시 엽니다. 다시 시작하면 해당 세션에서 실행 중인 작업도 종료됩니다. 실행 중인 프로세스를 유지하려면 재시작 옵션을 사용하지 마세요. PID가 다른 프로세스에 재사용됐거나 기록이 일치하지 않으면 프로세스를 종료하지 않습니다.

데스크톱을 다시 시작하지 않고 자동 제어만 끄려면 다음 명령을 실행하세요.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\rollback.ps1
```

백그라운드 서비스가 비정상 종료돼도 롤백 스크립트는 오프라인으로 자동 제어를 끄고 대기열을 보존합니다. 상태 기록이 손상된 경우 원본 파일을 덮어쓰지 않고 오류를 알립니다. 세션 브리지 자체가 비정상 종료된 경우에도 일반 Codex 실행 경로를 사용할 수 있으며 원클릭 롤백으로 기록된 데스크톱을 다시 열 수 있습니다. **이미 끊어진 stdio 세션의 프로세스를 세션 상태를 그대로 유지하면서 교체할 수는 없습니다.** 브리지 장애가 발생할 때마다 작업이 자동으로 끊김 없이 복구되는 것은 아닙니다. 이후 독립 모니터와 전용 실행 스크립트를 다시 실행하면 플러그인을 재설치하거나 영구 비활성화하지 않고 자동 제어를 복구할 수 있습니다.

## 마이그레이션, 데이터 보호 및 도구

시작 환경 변수의 영구 저장값을 변경하는 코드는 `scripts/migration.ps1`의 이전 버전 복구 로직뿐입니다. 현재 값이 이 플러그인의 것으로 확인된 이전 브리지 경로와 정확히 일치할 때만 신뢰할 수 있는 백업 값을 복원하거나 기존 값을 지우며, 쓰기 직전에 다시 확인합니다. 설정되지 않은 값은 그대로 두고, 다른 경로를 덮어쓰거나 사용자 수준의 백업을 시스템 수준에 적용하지 않습니다. 설치 시 `setx`를 사용하거나 레지스트리를 직접 수정해 실행 경로를 바꾸거나 예약 작업을 등록하지 않습니다.

Codex의 로그인 자격 증명, 세션, 프로젝트, 다른 플러그인의 설정은 삭제하거나 다시 쓰지 않습니다. 이전 `state.json`은 그대로 보존하며 그 안의 작업은 자동 실행하지 않습니다. 새 대기열은 `automation-state.json`에 저장합니다. 이 파일에는 재개할 요청의 본문이 들어가며, 플러그인 토큰과 함께 접근이 제한된 플러그인 데이터 디렉터리에 보관합니다.

사용할 수 있는 MCP 도구는 `guard_status`, `guard_check_now`, `guard_enable`, `guard_disable`, `guard_configure`, `guard_automation_status`, `guard_safe_mode`, `guard_cancel_pending`입니다. 도구를 통한 활성화는 기존 연결에만 적용됩니다. 일반 방식으로 연 데스크톱을 자동 제어 세션으로 전환하지 않습니다. MCP 초기화와 도구 검색은 오프라인에서도 가능하며 한도 조회용 백그라운드 서비스를 시작하지 않습니다.

아래 `doctor.mjs` 명령의 `C:\path\to\codex.exe`는 설치된 원본 Codex CLI의 실제 경로로 바꾸세요.

```powershell
npm run check
npm run build
npm test
node .\scripts\doctor.mjs --backend "C:\path\to\codex.exe"
```

플러그인을 제거하려면 다음 명령을 별도로 실행하세요.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\uninstall.ps1
```

제거 스크립트는 플러그인의 모니터를 중지하고 자체 시작프로그램 항목을 제거하며 이전 버전이 변경한 실행 경로를 복구합니다. 데이터는 보존하며, `-RemovePlugin`을 명시한 경우에만 Codex에서 이 플러그인의 등록을 해제합니다. 자동 제어 세션에서 제거한 경우에도 요청은 계속 원본 엔진으로 전달됩니다. 실행에 사용 중인 파일을 삭제하려면 해당 세션을 먼저 정상 종료하세요. 확인한 동작과 아직 검증하지 않은 항목은 [수정 사항 검증 기록](repair-validation.md)에서 확인할 수 있습니다.
