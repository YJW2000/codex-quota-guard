# 0.3 修复与验证记录（2026-11-18）

## 原因和证据

审计基线：0.1 提交 `25ab184`；0.2 独立监控提交 `a0df9e3`。

0.1 的 `scripts/install.ps1` 用 `[Environment]::SetEnvironmentVariable(..., 'User')` 设置启动覆盖；`scripts/start-codex.ps1` 设置进程变量；卸载尝试恢复原值。未找到 `setx`、直接注册表启动覆盖、系统级安装覆盖或计划任务注册。原生托盘/防睡眠自启动依附旧桥接可执行文件。

只读检查当前桌面安装包 `app.asar`：启动配置探测通过原生 CLI 的 `app-server --print-startup-config --startup-client-info ...` 完成，stdin 为 ignore。Windows 桌面 app-server 通过 stdio 接入，当前版本的共享守护进程路径限于非 Windows，未发现可供独立监控安全接入现有引擎的受支持控制接口。

0.1 `native/Launcher.cs` 只按参数中存在 app-server 判断长期桥接，没有排除启动配置探测。Node `src/bridge.mjs` 的 app Peer 在 stdin EOF 后关闭；原版 CLI 返回一次性 JSON 时，向已关闭 Peer 发送导致输出丢失，且子进程 exit 提前结束输出流。此前初始化/额度读取测试没有覆盖 stdin=ignore 的启动探测。

用本机 CLI `codex-cli 0.169.0-alpha.11.1`，桌面版本 26.1111.2228，以相同启动探测参数、stdin=ignore 对照：

| 程序 | 退出码 | stdout 字节 | 有效 JSON |
| --- | --- | --- | --- |
| 原版 CLI | 0 | 122 | 是 |
| 原始 0.1 桥接 | 0 | 0 | 否 |
| 修复 0.3 桥接 | 0 | 122 | 是，与原版一致 |

这定位了旧桥接在桌面启动配置路径上的具体缺陷，支持用户报告的故障因果链；未主动重启真实 GUI，故不能宣称已完整复现/验证 GUI 提示、组织设置 UI 或登录恢复。

## 修改文件和行为

- `native/Bridge.cs`：恢复经过修正的可选桥接；启动配置、help/version、生成命令直通原版；保留 Windows 参数引用和明确句柄继承；缺少 Node/脚本或配置失败时按已知原版路径直通，取消硬编码版本拒绝启动。
- `src/bridge.mjs`：原始 JSONL 转发、双向请求和未知字段保留；内部 RPC 标识隔离；EOF 等待输入/输出排空；保留原退出码；监控不可用或门禁超时放行。排队采用提案/落盘确认，未确认请求不能后台重放；保留审批跟踪、取消日志和后台重连。退出时清理尚在建立的连接。
- `src/automation.mjs`、`src/guard-service.mjs`：恢复多聊天/子任务暂停、持久队列、按账号去重恢复、同聊天顺序派发、防睡眠、取消/归档/审批处理。不因未知额度中断，不凭时间猜测恢复；派发结果不确定转人工确认。
- `src/daemon.mjs`、`src/main.mjs`、`src/mcp.mjs`、`src/quota.mjs`、`src/reader.mjs`：保留独立只读监控，接入可选自动控制、配置和管理工具。自动账本损坏不阻塞独立监控；无后端时 MCP 初始化仍可用。
- `native/Monitor.cs`：保留托盘，显示自动控制连接数/待恢复任务，提供可恢复安全模式和重新启用入口。
- `scripts/start-guarded-codex.ps1`、`scripts/preflight.mjs`：先比对启动配置、验证初始化和只读配置协议，再只在新桌面子进程环境设置覆盖；预检失败启动普通桌面，不结束已有桌面。
- `scripts/rollback.ps1`、`scripts/safe-mode.mjs`、`rollback.cmd`：在线/离线退出自动控制并保留插件/队列；可核对 PID、路径、启动时间后把记录的桌面用普通环境重新打开。拒绝结束身份不符进程。
- `scripts/install.ps1`、`scripts/build.ps1`：构建并安装两个独立用途的程序，升级前核对运行中的本插件进程，不覆盖正在执行的桥接。安装/自启动/卸载沿用 0.2 的保护机制；`scripts/migration.ps1` 是唯一持久变量修复写入点，无新增全局覆盖写入。
- `plugin.json`、`.codex-plugin/plugin.json`、`package.json`、技能、README、CI 和测试：更新 0.3 能力及使用/回退流程。插件身份与发布范围不变。

- 没有实际耗尽账户额度，也没有用真实聊天批量中断/续跑。自动控制通过模拟引擎和本机真实管道验证。
- 未在真实桌面重新载入插件或打开新版托盘 UI；MCP 初始化/工具测试在命令行子进程中完成。

- 监控故障会放行；这种情况下不能承诺额度保护仍生效。监控恢复后自动重连。桥接本身崩溃时无法无损迁移现有 stdio 会话；使用一键回退或普通 Codex 入口重新打开。全局覆盖不存在，因此下一次普通启动不会再次被旧桥接锁住。

- 0.1 的旧 state.json 原样保留，不自动导入执行，防止重放用户已在恢复期间完成的旧任务。新自动控制队列保存在独立账本中。
