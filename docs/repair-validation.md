# 0.2 独立监控修复与验证记录

## 已确认事实与原因边界

用户报告删除用户级 CODEX_CLI_PATH 并重启 Windows 后，Codex 桌面端恢复。代码审计确认 0.1 安装脚本设置该用户变量，专用启动脚本设置进程变量，卸载脚本尝试恢复旧值；未发现 setx、直接注册表写入、系统级覆盖安装或计划任务注册代码。旧 native/Launcher.cs、src/bridge.mjs 与 controller.mjs 负责代理桌面引擎并拦截任务。它们现在已删除。

这证明不恰当的启动耦合是必须移除的设计问题，**未证明桥接内部哪个错误导致“无法加载组织设置”**。先前成功的协议握手与模拟测试不能证明真实桌面登录可用。

## 当前实现

- 原生组件仅为 codex-quota-monitor.exe 托盘，不实现 Codex CLI 或 stdio 代理。
- src/reader.mjs 单独启动原版 CLI，只初始化并读取 account/rateLimits/read，使用总时限，失败只终止自身持有的查询子进程。
- src/monitor.mjs 将失败、退出、无数据或过期状态变为“暂不可用”，清空额度展示；无全局门禁或自动续跑。
- src/client.mjs / mcp.mjs 初始化、发现与状态查询不自动启动后台，离线返回不可用；不把监控服务器标为 required。
- 安装、重复安装和卸载共用精确路径迁移。只有当前覆盖属于旧插件时，才删除或恢复已记录值；覆盖为空或用户另设路径时不动它。
- 不改写 Codex 登录、会话、项目、其他插件文件。插件注册/移除为显式选项，使用原 CLI 的本插件操作。旧任务账本 state.json 保留，永不读入执行。

## 实际验证

1. Windows 上编译独立托盘；验证配置入口能运行，app-server 参数被拒绝，无法作为桌面引擎代理。
2. 在独立临时目录执行安装、重复安装更新、可选 Startup 快捷方式、卸载。逐个比较 User/Machine/Process 三层启动变量，均未新增或改变全局覆盖。
3. 对隔离 Codex 数据样本（auth.json、config.toml、会话、项目、其他插件配置）作逐字节比较，内容不变；旧恢复队列文件同样保持不变。
4. 覆盖旧路径删除、旧备份恢复、无覆盖不复活、大小写/引号归一化、相同文件名的其他路径保留、外部自启动项保留。
5. 模拟真实 stdio 查询，验证成功、缺失、错误、超时、崩溃与过期；查询方法白名单只包含初始化和额度读取。禁用/重新启用期间旧响应不会重新填入已清空数据。
6. 杀死独立监控进程后，客户端显示暂不可用。另一个独立桌面替身进程继续存活；这只是进程隔离测试。
7. MCP 在后台缺失时仍能完成初始化和发现，并返回暂不可用；不创建查询后台或访问账号。
8. 使用当前安装的原版 CLI 执行一次真实只读额度查询，成功获得服务实际返回的窗口。本次未启动真实任务、未改动启动变量、未进行登录/退出登录。
9. 只读检查本机 User/Machine/Process 三层 CODEX_CLI_PATH 均为空；检查 HKCU/HKLM Run，没有旧桥接匹配项。

本机最终执行 npm run check、npm run build、npm test，25 项测试通过。测试结果以 npm test 的当前输出为准。新的 GitHub CI 结果须另行核实，不能沿用 0.1 的 CI 记录。

## 明确未验证

- 未主动退出或重启真实 Codex GUI，未执行桌面端登录、组织设置加载或退出登录回归。
- 未用真实额度耗尽来触发场景；监控故障通过受控模拟引擎验证。
- 未验证真实 Windows 注销/开机后的 Startup 执行、长时间稳定性、或所有未来 CLI 版本的协议兼容。
- 未在系统级环境变量中人为写入旧覆盖做破坏性试验；该分支通过决策测试和条件审计验证。
- 没有自动重新启用本机旧插件。已安装 0.1 缓存和旧脚本不得用于重新安装；应使用此修复源码运行安装，按需注册/启动独立监控。
