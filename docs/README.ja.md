# Codex Quota Guard 0.4.1

[简体中文](../README.md) · [繁體中文](README.zh-Hant.md) · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

Codex が報告する利用枠の残量を監視し、5 時間枠が残り少なくなるとチャットを一時停止します。待機中のリクエストをキューに保存し、枠が回復すると元のチャットで処理を再開します。待機中に Windows のスリープを抑止することもできます。ユーザー環境変数やシステム環境変数の CODEX_CLI_PATH で起動先を上書きする方式は廃止しました。通常の Codex の起動やログインは監視プロセスから独立しています。

## 旧バージョンで発生した起動障害

デスクトップアプリは起動時に `app-server --print-startup-config --startup-client-info ...` を実行します。このとき標準入力には `ignore` が指定されます。バージョン 0.1 のネイティブプログラムは、この単発の設定取得を長時間動作する RPC セッションとして扱っていました。標準入力が終了すると Node.js ブリッジがセッションを閉じ、その後に届いた設定を閉じた通信相手（Peer）に転送しようとして出力を失っていました。また、子プロセスの出力をすべて読み取った後の `close` ではなく、`exit` の時点で出力を終了する問題もありました。

同じ PC の純正 CLI と 0.1 のソースコードで動作を比較しました。純正 CLI は終了コード 0 で **122 バイトの有効な JSON** を返しました。旧ブリッジも終了コードは 0 でしたが、出力は **0 バイト** でした。修正版は純正 CLI と同じ **122 バイトの有効な JSON** を返しました。組織設定の読み込みに使われる起動処理の互換性問題は再現・修正済みです。実際の GUI での組織設定読み込みとログインの回帰テストは未実施です。

## 2 つの利用方法

**残量だけを監視する。** 独立した監視プロセスが、純正 CLI の `app-server` を読み取り専用で起動します。実行する操作は初期化と `account/rateLimits/read` です。トレイアプリとオプションの MCP ツールは、トークンで認証されたローカルの名前付きパイプから状態を読み取ります。取得失敗、タイムアウト、クラッシュ、データ欠落、期限切れの場合は「暂不可用」（現在取得できません）と表示し、推定値は表示しません。

**自動停止と再開も有効にする。** この Windows デスクトップ版では、タスクを実行するエンジンが専用の標準入出力（stdio）を使用します。確認したバージョンには、独立した監視プロセスが実行中のエンジンに接続できるサポート対象の共有制御インターフェースがありません。そこで、専用スクリプトから起動したセッションに限り、オプションのブリッジで自動停止と再開を行います。スクリプトは起動設定とプロトコルを検証し、新しく起動するデスクトッププロセスにだけ環境変数を設定します。通常のショートカットとユーザー・システムの環境変数はそのまま使えます。起動中のアプリを強制終了したり、実行中のプロセスにブリッジを挿入したりすることはありません。

- 残量のしきい値は既定で 5% です。サービスが報告する 5 時間枠（300 分）の残量がしきい値以下になると、接続中のエンジンが読み込み済みの各チャットについて再開情報を保存し、実行中のタスクを中断します。エンジンから確認できるサブタスクも対象です。
- 新しいリクエストは元のパラメーターとともに保存し、クライアント識別子で重複を除きます。キュー登録を確認してから登録を確定します。応答が失われた場合やタイムアウトした場合、確認できていないリクエストを自動的に再実行することはありません。
- 5 時間枠の残量がしきい値を上回り、アカウントが利用可能であることを確認すると、次の照会または利用枠の更新通知で元のチャットを再開します。既定の照会間隔は 30 秒、再接続間隔は 1 秒です。リセット予定時刻を過ぎただけでは再開しません。
- 同じチャット内のリクエストは順番に送り、異なるチャットは並行して再開できます。キャンセル・アーカイブ済みの処理や、別途チャットが進行して古くなったターンは再開しません。承認やユーザー入力が必要な場合は引き続き入力を待ちます。送信結果を確認できない場合は要確認とし、自動で再送しません。
- 残量が不明なときや監視に失敗したときは、自動停止と自動再開を見合わせ、通常のリクエストを純正エンジンに直接転送します。監視プロセスが復旧するとブリッジが再接続します。キューに待機中の処理があればスリープ抑止を要求でき、監視プロセスが終了すると要求は解除されます。
- 制御対象は、専用スクリプトで起動し、実際に接続済みのエンジンです。通常起動した別の Codex、他の端末やデバイスには作用しません。PC のスリープ中、ネットワーク切断中、プログラムの終了中は即時再開できません。

## インストールと再有効化

Windows、Node.js 22 以降、システムの .NET Framework 4.x が必要です。旧バージョンのキャッシュにあるスクリプトは使わず、**修正済みのソースディレクトリ**から実行してください。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-monitor.ps1
```

インストーラーはチェック、テスト、ビルドを実行してからプラグインのファイルを更新します。利用可能な CLI がなければ、独立監視には「暂不可用」と表示されます。このプラグインのブリッジが動作中の場合は上書きできません。先に旧セッションまたは旧トレイアプリを通常の方法で終了してください。スクリプトがプロセス名を指定して Codex を強制終了することはありません。独立監視の更新前には、このプラグインの監視プロセスとトレイアプリが停止します。更新後に `start-monitor.ps1` をもう一度実行してください。

自動停止と再開を使うには、作業を保存して **Codex を通常の方法で完全に終了**してから、Codex の外で開いた PowerShell で次を実行します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-guarded-codex.ps1
```

このスクリプトは Windows のアプリマニフェストから実際のデスクトップ実行ファイルを特定します。起動前の読み取り専用チェックでは、純正 CLI とブリッジが返す単発の起動設定が一致することに加え、初期化、`configRequirements/read`、`config/read` の成功を確認します。チェックに失敗すると通常の起動経路でデスクトップを開き、独立監視を維持します。ユーザー環境変数への書き込みはありません。チェックの成功は、実際の GUI でのログインを検証したことにはなりません。

起動後、今回のセッション識別子に対応するエンジンとのハンドシェイクが必要です。タイムアウトすると接続を確認できなかった旨が表示されます。トレイメニューの「查看自动控制」（自動制御の状態）で接続済みエンジン数を確認してください。0 件なら現在動作しているのは独立監視のみです。

Codex 内の MCP ツール登録を復元するには、`install.ps1 -RegisterPlugin` を明示して実行し、Codex のプラグイン設定で有効にします。登録対象はこのプラグインとそのマーケットプレイスのみで、監視プロセスを必須の依存関係には設定しません。独立監視とセッションブリッジは MCP に接続できなくても使用できます。`-AutoStart` は監視トレイ用のスタートアップショートカットだけを作成します。Codex の自動起動や起動先の変更は行いません。

## メール通知

5 時間枠と週間枠の通知は、登録した Gmail アカウントから同じ宛先へ送信します。初回登録時の既定の宛先は自分のアドレスです。5 時間枠の通知は、チャットの中断または保留が確認された時点で送られます。同じアカウントで残量がしきい値以下の間に複数のタスクが対象になっても、通知は 1 通にまとめます。

週間枠（10,080 分）の残量がしきい値以下になったことを独立監視が検出すると、デスクトップが未接続でもメールを送ります。週間枠の残量による一時停止はなく、残りの枠をそのまま使えます。サービスが週間枠しか返さない場合、5 時間枠の状態は「暂不可用」と表示されます。

インストール後、次のコマンドで現在接続している Gmail を確認・登録します。登録時に行うのはメールアカウントの識別とツールの利用可否の確認のみです。通知発生時は純正 CLI の一時セッションから Gmail の送信ツールを直接呼び出します。本文に含まれるのは利用枠と時刻の情報だけです。送信前の失敗には間隔を延ばしながら再試行します。送信結果を確認できない場合は、トレイメニューの「查看额度」（利用枠を表示）で要確認と表示します。

```powershell
node "$env:LOCALAPPDATA/CodexQuotaGuard/app/scripts/connect-gmail.mjs"
```

両方の通知を別のメールアドレスで受け取るには、`--recipient` で宛先を 1 件指定します。例のアドレスは実際の受信先に置き換えてください。

```powershell
node "$env:LOCALAPPDATA/CodexQuotaGuard/app/scripts/connect-gmail.mjs" --recipient "recipient@example.com"
```

同じ Gmail アカウントを引数なしで再登録すると、設定済みの宛先が維持されます。Gmail アカウントを切り替えて引数なしで登録した場合は、新しいアカウント自身が宛先になります。

## ワンクリックで通常起動に戻す・自動制御を再開する

ソースディレクトリまたはインストール先の **`rollback.cmd`** をダブルクリックすると、自動制御を無効にし、プラグイン、独立監視、再開待ちキューを保持します。専用スクリプトで起動したデスクトップの記録がある場合は、PID、実行ファイルのフルパス、起動時刻が一致することを確認してから終了し、通常の環境で開き直します。PID が再利用されている場合や記録が一致しない場合は、そのプロセスを終了しません。再起動はセッション内の実行中の作業を終了させるため、作業を続けたい場合は再起動オプションを使わないでください。

デスクトップを再起動せずに自動制御だけを無効にするには、次を実行します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\rollback.ps1
```

監視プロセスがクラッシュしても、ロールバックスクリプトはオフラインで自動制御を無効にし、キューを保持できます。状態ファイルが破損している場合は元のファイルを保持し、上書きせずにエラーを報告します。セッションブリッジ自体がクラッシュしても、通常の Codex 起動経路は利用でき、ワンクリックで記録済みのデスクトップを開き直せます。ただし、**切断された stdio セッションのプロセスを、進行中の作業を保持したまま置き換えることはできません**。自動制御を再開するには、独立監視と専用の起動スクリプトをもう一度実行します。プラグインの再インストールや恒久的な無効化は不要です。

## 移行・データの取り扱い・ツール

永続的な起動環境変数に書き込むのは、`scripts/migration.ps1` が旧バージョンの値を修復するときだけです。現在値がこのプラグインのものと確認できた旧ブリッジのパスと完全に一致する場合に限り、信頼できるバックアップから復元するか、その値を削除します。書き込み直前にも現在値を再確認します。未設定の値を復活させたり、別のパスを上書きしたり、ユーザー用のバックアップをシステム環境変数に適用したりすることはありません。`setx`、レジストリの直接変更による起動先の上書き、タスクスケジューラへの登録は行いません。

Codex の資格情報、セッション、プロジェクト、他のプラグインの設定は削除も書き換えもしません。旧 `state.json` はそのまま保持し、旧タスクを自動実行しません。新しいキューは `automation-state.json` に保存します。このファイルには再開待ちリクエストの本文が含まれるため、プラグインのトークンと同じ、アクセス制限のあるプラグインデータディレクトリに置かれます。

使える MCP ツールは `guard_status`、`guard_check_now`、`guard_enable`、`guard_disable`、`guard_configure`、`guard_automation_status`、`guard_safe_mode`、`guard_cancel_pending` です。有効化の対象は接続済みのエンジンで、通常のデスクトップから起動済みのセッションは制御対象に加わりません。MCP の初期化とツール一覧の取得はオフラインでも利用でき、照会用の監視プロセスを起動しません。

診断コマンドの `C:\path\to\codex.exe` は、純正の `codex.exe` が実際にあるパスに置き換えてください。

```powershell
npm run check
npm run build
npm test
node .\scripts\doctor.mjs --backend "C:\path\to\codex.exe"
```

アンインストールするときは、次のコマンドを個別に実行します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\uninstall.ps1
```

アンインストール時はプラグインの監視を停止し、このプラグインの自動起動項目を削除し、旧バージョンの起動先の上書きを修復します。データは保持され、`-RemovePlugin` を明示した場合のみ Codex でのプラグイン登録を解除します。ブリッジを使用中のセッションでは、アンインストール後もリクエストは純正エンジンに直接転送されます。実行ファイルを削除するときは、そのセッションを先に通常の方法で終了してください。検証済みの範囲と未検証の動作は[修正の検証記録](repair-validation.md)を参照してください。
